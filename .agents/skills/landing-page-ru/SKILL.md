# Landing Page (адаптация elayadesign/landing-page-design, MIT)

Лендинг — не главная страница. Он выигрывает одно намерение:
**одно предложение → одна аудитория → одно целевое действие.**

Часть A решает, что говорит страница и как она устроена. Часть B — визуальная система. Сначала A, потом B.

## Область применения

Применять ТОЛЬКО к: лендингам, промо-страницам, маркетинговым сайтам, страницам захвата лидов, их отдельным секциям и ревью таких страниц.

НЕ применять к: Telegram Mini App, дашбордам, админкам, внутренним инструментам, ботам, калькуляторам внутри продукта. Там действует дизайн-система проекта.

Если в проекте уже есть свои шрифты, цвета или токены — они важнее части B. Явная просьба пользователя важнее любого правила здесь.

# ЧАСТЬ A — Стратегия и структура

## A1. Intake

Собери до начала работы. Спрашивай только недостающее и одним списком, не по одному вопросу.

**Цель:** одно целевое действие (заявка, расчёт, звонок, Telegram, WhatsApp, покупка); что именно получает человек; что считается конверсией.

**Аудитория:** кто клиент (физлицо, перекупщик, B2B-импортёр, дилер); какую проблему решает; топ‑3 возражения; источник трафика (реклама, поиск, соцсети, Telegram-канал, рассылка); что человек уже знает, когда попадает на страницу.

**Доказательства:** реальные отзывы, кейсы, цифры, фото и видео сделок, гарантии, условия возврата.

**Ограничения:** язык(и) страницы, тон, визуальное направление, приоритет мобильной версии.

Если ответа нет — сделай разумное допущение, опиши его одной строкой и продолжай. Не останавливай работу.

## A2. Структура страницы

**Первый экран (обязательно)**
1. Заголовок: результат + аудитория
2. Подзаголовок: как именно, с конкретикой
3. Основная CTA: глагол + что человек получает
4. Один сигнал доверия: цифра, логотипы, короткий отзыв
5. Визуал: реальный продукт, фото, скриншот, видео

**Середина (аргументация)**
6. Проблема → решение
7. Выгоды, 3–5, через результат
8. Как это работает, 3 шага
9. Социальное доказательство

**Низ (снятие возражений)**
10. FAQ, 6–12 вопросов
11. Снятие риска: гарантия, прозрачные условия, что будет, если что-то пойдёт не так
12. Финальная CTA, та же, что наверху

Опционально: крупная секция-слоган (см. B11), если она подходит проекту.

## A3. Выбор макета

Выбери один и коротко объясни почему.

| Тип | Когда |
|---|---|
| **A. Hero + секции** | Продукт понятен с первого экрана. Самый частый вариант. |
| **B. Длинная история** | Нужно обучить и снять скепсис (например, первый ввоз авто из-за рубежа). |
| **C. Минимальная страница** | Тёплый трафик или короткое предложение: подписка, чек-лист, лист ожидания. |
| **D. Сравнение** | Поисковый запрос вида «X или Y», «из Кореи или из Китая». |

## A4. Правила конверсии

- Сообщение совпадает с источником: если трафик из рекламы, hero повторяет обещание объявления.
- Одна основная CTA. Никаких конкурирующих CTA на первом экране.
- Сначала выгода, потом функция.
- Конкретика: ❌ «Быстро и выгодно» → ✅ «Расчёт под ключ за 15 минут, цена фиксируется в договоре».
- Минимум одно снятие риска.
- Возражения — отдельная секция, а не сноска. Доказательство ставится рядом с утверждением, которое оно подтверждает.

## A5. Копирайтинг

**Формулы заголовка:** «{Результат} без {боли}», «{Категория} для {аудитории}», «{Результат} за {срок}».

**Подзаголовок:** 1–2 предложения: что это и для кого.

**CTA:** глагол + что получает человек. Никогда «Подробнее» или «Отправить». Примеры: «Получить расчёт», «Подобрать авто», «Написать в Telegram».

**Выгоды:** **жирная выгода** — пояснение или доказательство.

## A6. Порядок сборки

Hero → Выгоды → Как это работает → Доказательства → FAQ → Финальная CTA. Секция за секцией, без пересборки всей страницы на каждой итерации.

## A7. SEO / AEO

- `noindex` для страниц под рекламу и временных акций.
- Индексировать вечнозелёные предложения: title, meta description, внутренние ссылки, FAQ в формате «вопрос — ответ», FAQ schema там, где уместно.
- Для мультиязычных страниц: `hreflang` и отдельный URL на каждый язык.

## A8. Типичные ошибки

Много CTA на первом экране; размытое ценностное предложение; список функций без результата; доказательства спрятаны внизу; мобильная версия плохо читается; непонятен следующий шаг.

# ЧАСТЬ B — Визуальная система

Все значения берутся из правил ниже, а не придумываются по ходу. Если у проекта есть своя дизайн-система — она важнее.

## B1. Типографика

### Шрифты

**Обязательное условие:** шрифт должен поддерживать все языки страницы. Перед выбором проверь наличие кириллицы и хангыля.

| Языки страницы | Использовать |
|---|---|
| RU / EN | Geist Sans (кириллица с v1.3), Manrope |
| KO / KO+EN | Pretendard |
| Цифры, код, таблицы | Geist Mono |

**Не использовать:** Poppins (нет кириллицы), Geist Serif (нет кириллицы), Arial, Helvetica, Roboto, Open Sans — дефолтный «шаблонный» вид. Inter допустим как запасной (fallback), но не как основной шрифт.

- Один шрифт на сайт. Geist Mono — только для цифр, кода и данных.
- Без курсива в интерфейсе.
- Без сверхжирных начертаний (900/black). Максимум — semibold/bold.

### Правила текста

**Пунктуация по нормам языка.**
- RU: дефис в составных словах обязателен («из-за», «что-то», «Южно-Сахалинск»). Тире — длинное «—» с пробелами, не дефис. Кавычки — «ёлочки». Неразрывный пробел (` `) между числом и единицей: «15 минут», «2 000 000 ₽», а также после коротких предлогов и союзов («в», «к», «с», «и», «на»).
- EN: избегай дефисов-заменителей тире внутри предложений, используй «—».
- KO: без лишней латиницы в заголовках, `word-break: keep-all`, чтобы слова не рвались посередине.

**Без висячих слов.** Одно слово не должно стоять в последней строке. `text-wrap: balance` для заголовков, `text-wrap: pretty` для основного текста. Для RU дополнительно ставь неразрывные пробелы после предлогов.

**Русский текст длиннее английского на 15–30%.** Закладывай место: кнопки не фиксированной ширины, заголовки проверяй на 390px.

### Шкала размеров (Tailwind)

Никаких произвольных размеров (`text-[19px]`, `22px`, `1.4rem`). Если размер не попадает на шаг шкалы — округлить до ближайшего шага вниз вместе с его line-height.

| Класс | Размер | Line height |
|---|---|---|
| `text-xs` | 12px | 16px |
| `text-sm` | 14px | 20px |
| `text-base` | 16px | 24px |
| `text-lg` | 18px | 28px |
| `text-xl` | 20px | 28px |
| `text-2xl` | 24px | 32px |
| `text-3xl` | 30px | 36px |
| `text-4xl` | 36px | 40px |
| `text-5xl` | 48px | 1 |
| `text-6xl` | 60px | 1 |
| `text-7xl` | 72px | 1 |

Для кириллицы и хангыля на шагах `text-5xl`+ допустимо поднять line-height до 1.1, чтобы не слипались выносные элементы.

### Именованные стили текста

Каждый текст — один из стилей. В коде стиль определяется один раз как класс в kebab-case (`heading-1`, `body-4`, `button-md`, `caption-2`).

## B2. Отступы

Только эти значения: 0, 2, 4, 8, 12, 16, 24, 32, 40, 48, 64, 80, 96 px (токены Spacing-0 … Spacing-900).

Основные кнопки: 8px по вертикали, 12px по горизонтали (минимум). Высота тач-зоны на мобильных не меньше 44px.

## B3. Скругления

Только значения Tailwind. Вложенные элементы при зазоре меньше 32px: `внутренний радиус = внешний радиус − зазор`, если результат больше 2. Пример: карточка `rounded-2xl` (16px) с отступом 8px → внутренний элемент `rounded-lg` (8px).

## B4. Рамки и фоны

- Рамка карточки — со всех сторон или ни с одной.
- Фоны однотонные, без градиентов.
- Тёмная тема, фоны: `#000000` · `#181818` · `#1F1F1F` · `#272727` · `#313131` · `#131209`.

## B5. Hero

- Заголовок: градиент только на тексте, слева направо. Тёмная тема `#FFFFFF` → `#9B9B9B`, светлая `#000000` → `#666666`. Если у бренда свой цвет — использовать его.
- Заголовок и подзаголовок: max-width 680px (для RU допустимо до 760px).
- Переносы строк — по смыслу, не разрывая словосочетания.

## B6. Иконки

Phosphor, Solar или Iconamoon. Не Material Icons / Material Symbols. Иконки мессенджеров (Telegram, WhatsApp, KakaoTalk) — официальные, без перерисовки.

## B7. Анимация

- Базовая кривая `cubic-bezier(0.22,1,0.36,1)`, 500ms для положения и раскладки; hover по цвету и прозрачности — 300ms, не короче 200ms. Никаких `ease`, `linear`, `ease-in-out`.
- Анимировать только `transform` и `opacity`.
- Учитывать `prefers-reduced-motion`: вместо движения — простое изменение прозрачности.
- Навигация: компактная плавающая панель с размытием фона; иконка меню анимированно меняет состояние; на мобильных меню — панель во всю высоту; ссылки появляются по очереди (сдвиг 24px, шаг 60ms, вся последовательность не дольше 400ms).
- Появление секций при скролле: подъём на 32px + fade, 600–800ms, один раз. Через `IntersectionObserver` или `whileInView`, никогда не через неограниченный `scroll`-listener.

## B8. Реалистичный контент и факты

- **Никогда не выдумывать факты.** Цены, курсы, ставки пошлин и утильсбора, сроки доставки, гарантии, количество клиентов, отзывы, логотипы партнёров — только от пользователя или из реального источника. Нет данных — ставь явный плейсхолдер `{{price}}`, `{{testimonial}}`, `{{delivery_days}}`.
- Расчёты таможенных платежей не вписывать вручную — брать из калькулятора или файлов проекта.
- Пиши реальный текст, без «Lorem ipsum» и «Ваш заголовок здесь».
- Для прототипов с вымышленными данными: имена соответствуют региону аудитории, цифры не круглые, даты разные.
- Запрещённые штампы: RU — «инновационный», «лучший на рынке», «индивидуальный подход», «высокое качество», «широкий ассортимент», «команда профессионалов»; EN — «revolutionize», «supercharge», «cutting edge», «effortless», «world class», «next level».
- Регистр: как в предложении (только первое слово с заглавной) для заголовков и кнопок.
- Системные сообщения спокойные и конкретные: «Заявка отправлена, менеджер ответит в течение часа». Ошибки — что сломалось и что делать. Без восклицательных знаков.

## B9. Состояния

У каждого интерактивного элемента: hover, active (`scale(0.98)`), видимый focus, loading (скелетоны, не спиннеры), empty, error (инлайн и конкретно, никогда `window.alert()`). Никаких мёртвых ссылок `#`. Текущая страница отмечена в навигации.

## B10. Перед публикацией

- Ссылки на политику конфиденциальности и условия в футере (для RU-аудитории — согласие на обработку персональных данных, 152-ФЗ, рядом с формой)
- Брендированная 404
- Валидация форм на клиенте: email, телефон с маской и кодом страны, обязательные поля
- Ссылка «перейти к содержимому» для клавиатуры
- Cookie-баннер, где требует юрисдикция
- Фавикон
- `<title>`, meta description, `og:image`, теги для соцсетей и превью в Telegram
- Alt-текст на всех значимых изображениях
- Семантический HTML: `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`
- Проверка на ширине 390px: нет горизонтального скролла, текст не вылезает из кнопок, основная CTA видна на первом экране
- Lighthouse: performance и accessibility не ниже 90 на мобильных

## B11. Секция-слоган (опционально)

Крупный текст с главной выгодой, отдельно от hero, ниже по странице. Минимум две строки, Heading 3 – Heading 1. Анимация: слова по очереди переходят из приглушённого (25–35% прозрачности) в полный цвет по мере скролла, базовая кривая B7, через `IntersectionObserver` или `requestAnimationFrame`. При `prefers-reduced-motion` — сразу полный цвет.

Добавлять, если подходит тону проекта. Для строгих B2B-страниц можно пропустить.

# Формат результата

При создании лендинга с нуля до кода выдать:
1. Структуру страницы — секции и их порядок
2. Текст hero — заголовок, подзаголовок, CTA, строка доверия
3. Выгоды (3–5)
4. Как это работает (3 шага)
5. FAQ (6–12)
6. SEO: index или noindex, title и meta
7. Тип макета (A/B/C/D) и почему
8. Список плейсхолдеров `{{...}}`, которые должен заполнить пользователь

Затем собирать по секциям (A6). После правок в JS-файлах — `node --check <file>`. Не трогать файлы вне задачи.

# Чеклист

**Стратегия**
- [ ] Одно предложение, одна аудитория, одно действие
- [ ] Нет конкурирующих CTA на первом экране
- [ ] Конкретика вместо общих слов
- [ ] Есть снятие риска
- [ ] Доказательства рядом с утверждениями

**Визуал**
- [ ] Шрифт поддерживает все языки страницы
- [ ] Пунктуация по нормам языка, неразрывные пробелы в RU
- [ ] Все размеры на шкале, все тексты — именованные стили
- [ ] Отступы только из таблицы, вложенные радиусы по формуле
- [ ] Нет фоновых градиентов и односторонних рамок
- [ ] Анимации на базовой кривой, есть `prefers-reduced-motion`

**Контент и запуск**
- [ ] Ни одного выдуманного факта, цены или отзыва; недостающее — в `{{плейсхолдерах}}`
- [ ] Нет штампов из списка B8
- [ ] Все состояния элементов на месте, нет мёртвых ссылок
- [ ] 404, юридические ссылки, согласие на ПДн, валидация, фавикон, meta, OG, alt
- [ ] Проверено на 390px
