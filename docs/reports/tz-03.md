# TZ-03 report — inspector voice + paint-gauge video → findings with timestamps

Done by Claude (Muse Code limit was spent on TZ-02/08/09). Live runs on the real MINI inspection video `demo-data/mini-cooper-s/video/paint_gauge.mp4` (150 s, 848×464, AAC audio). Raw output below.

## Key facts found during the work
- All inspection videos of all 5 cars carry audio; the inspector **dictates gauge values** while measuring.
- Muse Voice Transcribe returns plain text without word timings (`turns: []`) → audio is cut into 15 s chunks, chunk offset = timestamp.
- Video is Telegram-compressed (848×464): gauge **digits are not readable** even after SAM crops the screen (`digitsRead=0`), but the screen **colour band** is (orange/red on the hood). The tool never invents microns.
- Spark needs a larger output budget for long JSON (`maxTokens` 8000) — with 2000 the reasoning ate the budget and content came back empty.

## Tools
- `src/lib/meta/asr.ts` — `transcribeWav()` (multipart, Muse Voice Transcribe).
- `src/lib/agent/tools/voice.ts` — `transcribeNote()` = transcribe_note: ffmpeg 15 s WAV chunks → ASR (3 parallel) → Spark extracts per-panel readings + the inspector's own verdict + notes, each with a verbatim quote that must exist in the chunk (else rejected) → one finding per panel (merged readings, all quotes as evidence). Inspector's verdict beats the numeric rule; "factory" with numbers >150 becomes a **conflict** for the verifier (MINI contrast roof).
- `src/lib/agent/tools/gauge.ts` — `readGaugeVideo()` = read_gauge_video: frames → Spark vision batches (gauge visible, panel, screen colour, digits only if readable) → SAM screen crop re-read → per-panel measurements with second-level evidence.
- CLI: `npx tsx scripts/read-voice.ts <car> [--video f]`, `npx tsx scripts/read-gauge.ts <car> [--max-frames N --reread N]`.
