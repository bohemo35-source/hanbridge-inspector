# ТЗ-08 — 3D motion-сцена «Путь машины»: Корея → мост → порт → море → Владивосток → РФ/СНГ

Сначала прочитай AGENTS.md, `docs/tz/06_3d_damage_map.md` и `docs/reports/tz-06.md`. Выполни задание целиком, без промежуточных вопросов; что не выходит за 2 попытки — в отчёт и дальше. Ветка `tz-08` от `main` (3D-карта ТЗ-06 должна быть влита) → PR. Не пушить в main, не деплоить в прод без «делай» от Артура.

## Цель
Киношная scroll-сцена, которая показывает клиенту путь его машины после осмотра: та же машина из 3D-шаблона кузова (ТЗ-06) едет из Кореи через мост и порт, плывёт морем, прибывает во Владивосток и уходит дорогой в РФ/СНГ. Этапы связаны с данными: текущий этап клиента подсвечен по `get_shipping_status`. Фоны этапов сгенерированы **Muse Image** (номинация Best Creative), геометрия — кодом.

## Жёсткие правила (хакатон)
- Всё пишется с нуля. Никакого кода, моделей, текстур и ассетов из Hanbridge Auto (Bolt), Landing_Exportal_muse, Hanbridge_3D_lab, Kimi, unitedcarriers — только идея.
- Машина — только `buildCar(bodyType)` из `src/components/damage-map-3d/buildCar.ts` (импортировать, не копировать). Без логотипов и узнаваемых марок.
- Мосты, порт, корабль, город — обобщённые, низкополигональные, построены кодом (без копирования реальных архитектурных объектов один-в-один).
- Растры только от Muse Image этого проекта; промпты сохраняются в репо (провенанс).

## Этапы (id фиксированы — их же возвращает `get_shipping_status`)
| id | RU / EN | Что в кадре |
|---|---|---|
| `inspection` | Осмотр в Корее / Inspection in Korea | площадка, машина под софтбоксом, вспышка «Report ready» |
| `korea_road` | Дорога и мост / Road & bridge | ночная трасса, вантовый мост над заливом, огни |
| `port_busan` | Порт отправки / Departure port | краны, контейнеры, машина заезжает в ro-ro |
| `sea` | Море / Sea crossing | корабль на волнах (шейдер), камера облетает |
| `vladivostok` | Владивосток / Vladivostok | вантовый мост и сопки на рассвете, выгрузка |
| `customs` | Таможня / Customs clearance | ворота, штамп-анимация «Cleared» (без цифр пошлин) |
| `delivery` | Доставка в РФ/СНГ / Delivery to RF/CIS | длинная дорога к горизонту, финальный кадр с машиной |

## Что сделать
1. `src/components/journey-3d/`:
   - `route.ts` — маршрут как `CatmullRomCurve3` по 7 опорным зонам; `stageAt(progress: 0..1): StageId`, `progressOf(stage)`; чистые функции, без three-рендера.
   - `scenery.ts` — генераторы: дорога с разметкой (instanced), вантовый мост (пилоны + ванты линиями), краны/контейнеры (InstancedMesh), корабль ro-ro (простые объёмы), вода (ShaderMaterial: волны в вершинном шейдере, френель), сопки (noise-heightfield), городские огни (Points). Бюджет на всю сцену `< 250 000` треугольников.
   - `JourneyScene.tsx` — `"use client"`, Three.js. Скролл секции (sticky, высота 700vh) → `progress` → камера едет по кривой (сглаживание), машина движется по своей кривой (на этапе `sea` стоит на палубе корабля). Свет и туман меняются по этапу (ночь → утро во Владивостоке). Подпись этапа (RU/EN по `lang`) появляется/уходит по прогрессу. Фон этапа — плоскость/купол с текстурой из `public/journey/<stage>.jpg`, кросс-фейд между этапами.
   - props: `{ bodyType, doors?, lang, currentStage?: StageId, compact?: boolean }`. `currentStage` → маркер «Ваша машина здесь» и пульс на этапе; этапы после текущего чуть приглушены.
   - Фолбэк без WebGL и при `prefers-reduced-motion`: вертикальная лента 7 карточек (фон этапа + подпись + отметка текущего этапа).
   - Eco: средний FPS за 2 с < 40 → выключить шейдерные волны (статичная вода), туман проще, pixelRatio 1. Мобильный: pixelRatio ≤ 1.5, высота секции 500vh.
2. Фоны Muse Image: `scripts/journey/generate-backdrops.mjs` — 7 запросов `POST /images/generations` (`muse-image-1.0`, ~23 c каждый, последовательно), сохраняет `public/journey/<stage>.jpg` (≤ 1600 px, JPEG q80) и `public/journey/prompts.json` (промпт, модель, дата). Стиль единый: кинематографичный, сумерки/рассвет, мягкая дымка, без людей, без текста, без логотипов и узнаваемых брендов. Запускать один раз; картинки коммитятся.
3. Связка с данными: `src/lib/agent/tools/shipping.ts` — `getShippingStatus(reportId)` возвращает `{ stage: StageId, etaDays?: number, source: "demo_fixture" }` из `src/lib/agent/fixtures/shipping.json` (для 5 демо-машин разные этапы). Этот же инструмент использует агент в ТЗ-05.
4. Где показывать:
   - главная `/`: hero-секция с `JourneyScene` (машина-хэтчбек, без `currentStage`), сверху заголовок продукта и кнопка «Каталог осмотров» → `/cars`;
   - `/lab/journey?stage=<id>&body=<type>&lang=ru|en` — демо-страница для записи видео;
   - для ТЗ-05: экспорт `<JourneyScene compact currentStage=… />` для вкладки «Доставка» в `/r/:id` (подключит ТЗ-05).
5. Тесты (vitest, без сети и WebGL): `stageAt`/`progressOf` (границы и монотонность), все 7 этапов достижимы, `getShippingStatus` возвращает валидный этап для каждой демо-машины, бюджет треугольников генераторов (`< 250 000`).
6. Скриншоты: расширить `scripts/3d/capture.mjs` (или новый `scripts/journey/capture.mjs`) — кадры каждого этапа через `/lab/journey?stage=…`, мобильный кадр, фолбэк `?no3d=1`.
